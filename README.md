# A pediatric ultra-widefield fundus image dataset for artery-vein segmentation

This repository contains the preprocessing, five-fold cross-validation,
training, evaluation, and inference code associated with the "A pediatric ultra-widefield fundus image dataset 
for artery-vein segmentation" study. The dataset is distributed separately through
Figshare and is intentionally not stored in this GitHub repository.

The experiments evaluate three segmentation models: UNet, ResUNet, and Attention UNet.

All architectures predict five classes: background, artery, vein,
artery-vein crossing, and uncertain.

## Repository structure

```text
preprocessing/
  data_preprocess_demo.py demonstrate preprocessing one image and its JSON annotation
prepare_kfold_data.py    create five-fold train/validation/test data
run_training.py          train one or more model architectures
run_test.py              evaluate checkpoints over all folds
predict.py               generate color-coded masks from one checkpoint
models.py                shared architecture definitions
dataset.py               PyTorch dataset
utils.py                 normalization and evaluation utilities
```

The source images and source JSON annotations used by the preprocessing demo are
not distributed. Most users should download the processed dataset from Figshare
and start from the k-fold preparation step.

## Download the dataset

Download the PUWF-AV dataset from [Figshare](https://doi.org/10.6084/m9.figshare.32509329).
Please cite the dataset when using it in publications or derived work.

Extract the archive into `PUWF-AV/` by default:

```text
PUWF-AV/
  images/
  annotation/
  fov/
```

The dataset can be stored elsewhere. Pass its root folder with
`--dataset-folder`; the default remains `PUWF-AV` relative to the repository.

## Installation

The experiments were run in a Linux environment with an NVIDIA RTX 4090.
Python 3.10 or newer is recommended.

```bash
python -m venv .venv
```


```bash
source .venv/bin/activate
```

Install PyTorch and torchvision first using the command generated by
the [official PyTorch installation selector](https://pytorch.org/get-started/locally/).
The code was tested with PyTorch 2.6.0 and torchvision 0.21.0. Then install the
remaining project dependencies:

```bash
python -m pip install -r requirements.txt
```

Every executable script automatically selects CUDA when available and otherwise
uses the CPU. Multi-GPU training is not used.

## Prepare the five-fold data

```bash
python prepare_kfold_data.py \
  --dataset-folder PUWF-AV \
  --output-folder kfold_set \
  --folds 5 \
  --patch-size 512 \
  --stride 256 \
  --seed 123
```

Example with the Figshare data stored outside the repository:

```bash
python prepare_kfold_data.py --dataset-folder /path/to/PUWF-AV
```

## Train

The following command shows every training option and its default value:

```bash
python run_training.py \
  --dataset-path kfold_set \
  --loss-record-path loss_record \
  --checkpoint-path checkpoint \
  --models unet resunet attentionunet \
  --folds 5 \
  --image-size 512 512 \
  --lr 0.001 \
  --batch-size 32 \
  --num-epochs 30 \
  --patience 8 \
  --num-workers 4 \
  --seed 123
```

This command trains all three models across five folds. `--no-amp` is the
remaining available option; it is omitted above because CUDA automatic mixed
precision is enabled by default. Add `--no-amp` to disable it. To train only
one architecture, for example:

```bash
python run_training.py --models unet
```

Outputs are organized as follows:

```text
checkpoint/<model>/fold_N/checkpoint_epochE.pth
loss_record/<model>/fold_N/loss_record_<timestamp>.csv
```

## Evaluate

The following command shows every evaluation option with its default value:

```bash
python run_test.py \
  --dataset-path kfold_set \
  --loss-record-path loss_record \
  --checkpoint-path checkpoint \
  --output-path test_results \
  --models unet resunet attentionunet \
  --image-size 512 512
```

Summary tables are saved as `test_results/test_result_<model>.csv`. For each
fold, the epoch with the highest validation Dice score is evaluated. The
remaining available option, `--loss-selection-manifest`, is optional and has
no default file. Use it only when a model/fold directory contains multiple loss
CSV files.

Each model/fold loss directory must contain exactly one CSV. If multiple CSVs
are present, evaluation stops instead of selecting one implicitly. Create a JSON
file such as `loss_selection.json` to select the intended experiment:

```json
{
  "unet": {
    "fold_1": "loss_record_20260807_120000.csv",
    "fold_2": "loss_record_20260807_130000.csv"
  },
  "resunet": {},
  "attentionunet": {}
}
```

Include an entry for every model/fold directory that contains more than one CSV,
then run:

```bash
python run_test.py \
  --models unet resunet attentionunet \
  --loss-selection-manifest loss_selection.json
```

## Predict

Inference uses the RGB parameters from the fold that produced the checkpoint.
For example:

```bash
python predict.py \
  --model unet \
  --model-path checkpoint/unet/fold_1/checkpoint_epoch7.pth \
  --normalization-csv kfold_set/fold_1/train_rgb_parameters.csv \
  --image-path PUWF-AV/images \
  --fov-path PUWF-AV/fov \
  --output-path predictions/unet_fold_1
```

Annotation and prediction colors are stored in OpenCV BGR order:

- black: background
- red: artery
- blue: vein
- green: artery-vein crossing
- white: uncertain annotation

## Demonstrate preprocessing from source data

This step is not required when using the released `PUWF-AV` dataset. The demo
is kept only to show the complete preprocessing flow for one image and its
corresponding LabelMe-style JSON file. It does not scan a directory, infer
filename mappings, or rename files: all three outputs retain the original
image filename.

```bash
python preprocessing/data_preprocess_demo.py \
  --image-path /path/to/image.png \
  --annotation-path /path/to/image.json \
  --output-folder PUWF-AV-demo
```
